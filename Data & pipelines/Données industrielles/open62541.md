## Définition

Implémentation d'**OPC UA** (IEC 62541) en langage C. Elle fournit une bibliothèque de
**client** et de **serveur**, avec un modèle d'information complet (tous les types de nœuds, méthodes,
ajout et retrait de nœuds à l'exécution), des abonnements, un historique de base, un chargeur de
modèles NodeSet XML et un sous-système **PubSub**. Le code propre à une plate-forme est isolé dans des
plug-ins (`EventLoop`, architecture, cryptographie, stockage de l'espace d'adressage) : c'est ce qui
permet de la porter sur du matériel embarqué. Une distribution « amalgamée » (`open62541.c` et
`open62541.h`) tient en deux fichiers à ajouter à un projet existant.

Relevé le 2026-10-01 : **v1.5.8** du 2026-09-06 (publiée le même jour que les correctifs 1.4.20 et
1.3.21), 3 233 étoiles, dernier commit du 2026-09-30, dépôt créé en 2013. Trois séries sont maintenues
d'après `SECURITY.md` : 1.5 (stable), 1.4 et 1.3. Versions récentes : 1.5.5 (2026-06-28), 1.5.6
(2026-07-27), 1.5.7 (2026-08-20) : une version tous les mois environ.

## Prendre si / Écarter si

| Prendre si | Écarter si |

## Mise en œuvre

- Installation — CMake, `cmake` puis `make` ; `UA_ENABLE_ENCRYPTION` est à `OFF` par défaut, à passer à `MBEDTLS` ou `OPENSSL` pour la sécurité ; sous Debian et Ubuntu, `apt install libopen62541-1.4-dev` (série 1.4, d'après le README)
- Point d'entrée — créer un `UA_Server` ou un `UA_Client`, y ajouter des nœuds ou lire des variables ; exemples dans `examples/`
- Prérequis — un compilateur C99, CMake 3.13 ou plus ; mbedTLS ou OpenSSL pour les politiques chiffrées
- Exécution — bibliothèque liée à l'application, rien à héberger ; la doc de la v1.5.8 annonce des binaires serveur « bien en dessous de 100 ko » selon le modèle d'information (chiffre de la documentation, non mesuré ici) ; testées en CI : Linux, Windows, macOS, Zephyr, FreeRTOS ; QNX et VxWorks sans CI (`arch/README.md` de la v1.5.8)
- Coût — gratuit pour la bibliothèque ; support payant chez o6 Automation GmbH, dont les tarifs ne sont pas repris ici faute de lecture directe

## Licence et gouvernance

- **MPL-2.0** pour le code de la bibliothèque (fichier `LICENSE`, texte intégral). Une partie des plug-ins et des exemples est en **CC0** (domaine public). Le README dit « certains plug-ins et exemples », la documentation de la v1.5.8 dit « les plug-ins et les exemples » : l'en-tête de chaque fichier tranche. Aucune double licence propriétaire dans le dépôt.
- **Ce que permet la licence** : la MPL-2.0 est une licence à copyleft *par fichier*. Le README précise que la bibliothèque se combine avec du code privé écrit dans des fichiers séparés, **y compris en liaison statique**, sans que ce code soit touché. Utiliser chez un client ou embarquer dans un produit livré est donc possible. Les modifications des fichiers MPL eux-mêmes se publient quand on les distribue ; un correctif interne dans `src/` est concerné, un plug-in écrit à côté ne l'est pas. L'amalgamation fusionne code MPL et code CC0 en un fichier : le modifier, c'est modifier du code MPL. **Lecture, sans valeur juridique.**
- **Pas de relicence possible** : les contributeurs gardent leur copyright individuel (README).
- **Gouvernance** : organisation GitHub « open62541 », pas de fondation. **o6 Automation GmbH** emploie les contributeurs principaux et vend le support ; l'offre commerciale couvre aussi les familles de versions anciennes (`SECURITY.md`). Le site cite parmi les contributeurs fortiss, basysKom, Wind River, HMS Networks, Fraunhofer IOSB et des universités.
- **Certification** : le README dit qu'un serveur d'exemple bâti sur la v1.4 a été certifié par l'OPC Foundation, profil *Standard Server 2017*. La fiche de l'OPC Foundation, lue par un résumeur de pages, donne un certificat portant la version 1.4.0-rc2 ; sa date est ambiguë dans la lecture. La page de certification du projet précise que cela vise le **serveur d'exemple**, pas toute application bâtie dessus. Aucune certification de la série 1.5 trouvée.

## Limites à connaître

- **PubSub annoncé expérimental.** Activé par défaut dans le CMake de la v1.5.8, mais la documentation le dit expérimental, et la v1.5.8 corrige du PubSub côté sécurité. Pour de la publication OPC UA sur MQTT en production, tester soi-même.
- **Alarmes et conditions : désactivées par défaut** (`UA_ENABLE_SUBSCRIPTIONS_ALARMS_CONDITIONS`, marqué expérimental). Les événements d'abonnement sont activés dans le CMake mais restent décrits comme expérimentaux dans la doc.
- **Historique en mémoire seulement** dans les plug-ins fournis (backend mémoire, collecte et base par défaut) ; pas de backend disque trouvé.
- **La sécurité est à activer.** Le chiffrement est `OFF` par défaut. Les notes de la v1.5.8 sont majoritairement des correctifs de robustesse : débordements de taille dans les décodeurs XML et JSON, validation d'en-têtes OPN, durcissement du PubSub, un use-after-free dans l'historique mémoire. Aucun avis de sécurité n'est publié sur GitHub (le projet passe par `open62541-security@googlegroups.com`) et les notes ne citent aucun CVE. Suivre la série 1.5 ou acheter le support d'une série ancienne.
- **Intégration en C.** Il n'y a pas de passerelle toute faite : tout se code. Les liaisons existantes sont des projets tiers, de tailles très inégales (ci-dessous).

## Écosystème

### Alternatives

- [[asyncua]] — Bibliothèque Python asynchrone, client et serveur OPC UA : lecture, écriture, abonnements, méthodes, historique, chiffrement X.509 et import de NodeSet XML ; LGPL-3.0, noyau de mainteneurs réduit, alarmes serveur non implémentées et pub/sub minimal. — la même norme, en Python pur : un script ou un service qui lit et publie, plutôt qu'un composant C à compiler et à porter.

### Compléments

Aucun complément déclaré : la publication vers un broker ou une base de séries se code autour de la bibliothèque, ou se confie à [[Telegraf]], qui lit n'importe quel serveur OPC UA par `inputs.opcua`.
