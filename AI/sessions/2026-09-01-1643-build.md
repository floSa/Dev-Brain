# Session build — intégration d'un lot de dépôts et d'outils

## Contexte

Lot de 15 briques repérées par l'utilisateur (dépôts GitHub + Superwhisper + BMAD), à intégrer d'un coup.
Orchestration : 5 agents de reconnaissance web en lecture seule, puis écriture. Les 6 agents d'écriture
lancés en parallèle sont tous tombés sur des erreurs API 529 (surcharge plateforme) ; 4 pages ont survécu
aux coupures, les 11 autres ont été écrites directement par l'orchestrateur. Le protocole anti-collision
(propriété exclusive des fichiers, aucun fichier partagé touché par les agents) a tenu : aucune perte,
aucun conflit.

## Décisions de catégorisation

- **Skills d'agent → `Dev/Outils/`**, pas `Wiki/Outils/` — cohérent avec les précédents Graphify et Spec Kit.
  Archify va en `tooling/diagram` (le discriminant est l'artefact produit, pas le véhicule de livraison).
- **`swarm-forge` : `licence_type` laissé VIDE** — le dépôt n'a aucun fichier LICENSE, donc aucun droit
  accordé au sens strict. Le déclarer `open-source` aurait été faux.
- **`public-apis` : fiché en `tooling/api` sur décision explicite de l'utilisateur**, malgré l'avis contraire
  de la reconnaissance (c'est un annuaire, pas un client d'API). La page l'assume en tête. `tags: []` faute
  de tag honnête dans le vocabulaire fermé.
- `Maka` et `swarm-forge` en `status: en-eval` (aucune release publiée pour l'un, ni licence ni versioning
  pour l'autre). `t3code` en `en-eval` (le README s'auto-déclare très instable).
- `freebuff` en `open-core` : dépôt Apache-2.0 mais backend modèles hébergé et propriétaire.
